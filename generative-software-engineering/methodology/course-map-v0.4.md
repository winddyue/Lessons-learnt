% 生成式软件工程课程地图

版本 V0.4 更新日期 2026年10月1日

这份地图回答三个问题：老师正在建立怎样的方法论，七份课程材料分别位于哪里，以及后续课程如何持续进入同一套知识体系。当前主线是把人的意图，通过规格、架构、上下文、Agent
执行、验证和版本管理，稳定地转化为可演进的软件。第 5、6 次课进一步补上了这套框架的历史根基：软件工程的对象不是某一次代码生成，而是需求、设计、代码、测试和运行结果构成的依赖网络；好的架构要让这个网络能够以较低代价应对变化。第 7 次课继续把“应对变化”具体化：用抽象和层次隔离复杂性，把事实、操作、派生状态和视图分开，使系统能够回放过去、解释现在并推演未来。

# 课程主线

生成式软件工程关注的核心问题，是如何构造一套工作环境，使 AI
能持续、可靠、可验证地把人的意图转化为软件。代码生成只是执行环节之一。人需要明确目标与约束，控制关键架构，组织上下文，建立验证证据，并管理每次变化。

| **阶段**          | **核心问题**                  | **主要产物**                     |
|-------------------|-------------------------------|----------------------------------|
| **Intent**        | 真正要解决什么问题            | 目标 边界 用户价值               |
| **Specification** | 怎样才算做对                  | 约束 验收标准 数据与接口规则     |
| **Architecture**  | 系统怎样组织并允许未来变化    | 边界 模块 状态和责任             |
| **Context**       | 当前任务需要让 Agent 看到什么 | 项目指令 相关文件 Skill 工具结果 |
| **Execution**     | AI 可以在多大操作空间内行动   | 候选方案 代码 操作和工作流       |
| **Verification**  | 什么证据能够证明结果正确      | 测试 校验 审核与评价标准         |
| **Versioning**    | 怎样保存 比较 回退和学习      | 提交 历史 决策 教训              |
| **Iteration**     | 下一步怎样以最小风险扩展      | MVP 小步变更 新一轮规格          |

# 老师的思维方式主线

前七课反复出现的不只是技术结论，而是一套稳定的观察方法。老师通常先问一个技术在历史上解决了什么根本问题，再判断今天哪些约束已经变化；他会在抽象层与实现层之间往返，用实际系统、代码和工具检验理解，并把 AI 当作阅读、翻译、追问、比较和实验的协作者。

| **观察角度** | **老师的典型思路** | **对我们的方法论启发** |
|---|---|---|
| **计算机观** | 计算机不断把昂贵稀缺的能力变成可普及的日用品 | 判断技术变革时先看什么能力的边际成本正在下降 |
| **软件观** | 软件是现实规则在计算世界中的可执行投影 不是代码文件的集合 | 从意图 规则 状态和证据理解软件 不从页面和代码量理解 |
| **操作系统观** | 操作系统通过稳定抽象与统一接口隔离设备和实现复杂性 | 好架构应让上层不必反复理解底层细节 |
| **架构观** | 架构的任务是驾驭复杂性 隔离变化并允许系统生长 | 用未来变化和认知负担评价架构 而非只看能否运行 |
| **历史观** | 经典工作记录一个领域最初也最根本的问题 | 回到原文与历史条件 区分原始洞见和教科书压缩后的标签 |
| **学习观** | 理解来自看得多 做得多 追问和对比 不是记住术语 | 建立原文 问题 解释 实验 反思的学习闭环 |
| **AI 观** | AI 是可无限追问的老师和研究助手 但答案仍需原文与实践校验 | 用 AI 扩展探索速度 人负责选题 判断 品位和证据 |

# 课程与项目关系

生成式软件工程学习实验室是通用方法论层。PFMEA Agent、个人知识 Agent
和供应商数字化系统是应用层。通用原则只维护一份，各项目记录自己的约束、实验结果和决策，不复制上位知识。

| **通用方法论**              | **PFMEA Agent 应用**                | **个人知识 Agent 应用**    | **供应商数字化应用**          |
|-----------------------------|-------------------------------------|----------------------------|-------------------------------|
| **Intent 与 Specification** | 七步法 数据模型 人机边界            | 记录 分类 评审和立项规则   | 业务目标 流程和验收标准       |
| **Context Engineering**     | 项目证据 领域知识 组织知识 当前状态 | 个人资料 当前任务 相关历史 | 主数据 业务规则 项目证据 权限 |
| **Verification**            | 结构规则 SOD 规则 证据继承          | 来源完整性 分类一致性      | 接口校验 流程状态 数据质量    |
| **Versioning**              | 状态操作 决策日志 模板版本          | 知识条目版本 观点演进      | 需求 规则 配置与发布版本      |
| **Traceability**            | 要求 功能 失效 原因 控制和证据链    | 来源 观点 结论和行动链     | 需求 流程 数据规则和测试链    |

# 知识流转方式

1\. 保留原始字幕作为 Evidence Layer，并登记文件名与关键时间点。

2\. 按课形成 Lecture Note，回答老师在解决什么问题以及使用了哪些案例。

3\. 把跨课程重复出现的判断提炼为 Principle Method Pattern 或 Anti
pattern。

4\. 只有稳定且重复的方法，才进入 Agent Skill 候选清单。

5\. 在 PFMEA 等真实项目中验证；实验结果回写知识库和学习日志。
